# CT-07 Lesson 01 — Image Editing Foundations, File Formats and Workspace

- Course: CT-07 — Photo & Image Editing
- Level: Foundation / Beginner
- Estimated time: 120–180 minutes
- Prerequisites: Basic computer/file management and image literacy
- Tools/environment: Any capable raster editor or RAW processor; record app/version, OS and color-management setup
- Version/review date: Tool-neutral; output specifications depend on print/web/client destination

## Learning outcomes
Identify raster image properties, choose suitable formats, preserve originals and organize a non-destructive editing project.

## Key definitions
- **Raster image:** Pixel-based image representation.
- **Resolution/dimensions:** Pixel count across width and height; print resolution also relates pixels to physical size.
- **Color profile:** Data describing how color values should be interpreted.
- **Layer:** Independent editable image/content element.
- **Mask:** Non-destructive control over layer visibility.
- **RAW:** Camera capture data requiring interpretation and processing.
- **Histogram:** Graph of tonal value distribution.
- **Provenance:** Record of image origin and transformations.

## Purpose and theory
Raster images are grids of pixels. Pixel dimensions, bit depth, color profile and compression influence editing and delivery. JPEG is typically lossy; PNG supports lossless compression and transparency; TIFF can store high-quality image data; RAW formats retain camera sensor data interpreted through a raw processor. Format choice depends on purpose, not file extension alone.

## Tools, requirements and alternatives
Use a suitable raster editor and, where needed, a RAW processor. Record exact versions and color-profile assumptions. Keep original images, use backups and work non-destructively. Only edit images you own or are authorized to use.

## Procedure
1. Inventory source files and confirm rights. 2. Record pixel dimensions, bit depth and color profile where available. 3. Identify RAW, raster and vector inputs. 4. Preserve original files and create a working copy. 5. Choose an editor appropriate to the task. 6. Set a color-managed workspace where supported. 7. Create layers/adjustment layers rather than destructive edits. 8. Save an editable project and export a delivery copy.

## Worked example
A product photo is edited from a RAW source, saved as a layered project and exported as a high-quality JPEG for web plus a transparent PNG graphic where needed.

## Dry run
A JPEG is repeatedly opened, edited and resaved, accumulating compression artifacts. Return to the original or master and export only once from the editable project.

## Guided practice
Create an organized project with a source inventory, layered edit and two delivery formats.

## Independent assignment
Repeat the workflow on a second image set with a different lighting or delivery condition. Submit source inventory, editable project, exports and a short rationale for key decisions.

## Common errors and recovery
| Symptom | Likely cause | Diagnosis | Recovery |
|---|---|---|---|
| Submit project, original-preservation proof, metadata notes and exports. | Workflow issue | Inspect source, settings and target requirements | Correct and retest |

## Knowledge check
1. Why preserve original image files?
2. How do layers and masks support non-destructive editing?
3. What can a histogram tell you, and what can it not tell you?
4. Why do batch presets require individual review?
5. What determines the correct delivery format?

## Answer guidance
1. They preserve source quality and allow recovery/revision.
2. They keep edits reversible and independently adjustable.
3. It shows tonal distribution but does not determine aesthetic correctness.
4. Source conditions and subject matter may vary.
5. Destination requirements, transparency, compression, profile and downstream workflow.
