# CT-02 Lesson 07 — Assembly, Rough Cut, Fine Cut and Picture Lock

- Course: CT-02 — Film & Cinematic Editing
- Level: Expert
- Estimated time: 5–6 hours
- Prerequisites: Lessons 01–06; approved script/brief and organized footage
- Environment: Any NLE; record version and project settings
- Version/review date: 1.0 — 2026-11-16

## Learning outcomes
Learners can distinguish assembly, rough cut, fine cut and picture lock; create reviewable versions; use notes without losing editorial intent; and define objective lock criteria.

## Terminology
| Term | Definition |
|---|---|
| Assembly | First ordered construction from selected material, often preserving broad coverage |
| Rough cut | A complete early version focused on story structure and scene order |
| Fine cut | Refined timing, performance, transitions, continuity and shot duration |
| Picture lock | Approved state after which picture edits are frozen for downstream finishing |
| Change list | Traceable record of requested and accepted revisions |
| Turnover | Organized handoff to sound, color, VFX, titles or mastering |

## Theory
Editorial refinement is iterative. Assembly tests whether the material can form a coherent whole. Rough cut tests story logic and overall duration. Fine cut improves exact choices and timing. Picture lock is not merely a feeling that the edit is finished: it is an agreed production state with version identity, approval and documented exceptions. A late picture change can affect sound, VFX, subtitles, color and delivery; therefore lock requires change control.

## Procedure
1. Confirm brief, script revision, scene/shot inventory and target runtime.
2. Build an assembly in scene order; retain handles and alternate performances.
3. Watch the assembly without polishing effects. Note missing story information, duplicated beats and structural gaps.
4. Create rough cut v1 with a clear beginning, middle and ending. Record runtime and unresolved story questions.
5. Present a review copy with version ID, timecode burn-in if requested, and a concise review brief.
6. Convert feedback into a change list. Separate objective errors, stakeholder requirements and subjective preferences.
7. Resolve conflicts against the approved brief and decision owner; do not silently accept contradictory notes.
8. Build fine cut v2: refine performance, shot duration, continuity, transitions, screen direction, audio bridges and scene rhythm.
9. Review the entire programme at normal speed. Check scene-to-scene flow, not only individual edits.
10. Run a technical pass for black frames, flash frames, offline media, sync, missing shots, temp titles and unapproved placeholders.
11. Obtain explicit picture approval. Record approver, date, version, runtime and outstanding exceptions.
12. Freeze a copy of the approved sequence; create turnover notes and a change-control process for any later revision.

## Worked example
A 4-minute scene contains three repeated reaction shots and an unclear motivation. In assembly, keep all plausible performances. In rough cut, remove repeated beats and test whether the motivation reads. In fine cut, adjust reaction timing and an L-cut to preserve emotional continuity. Lock only after the director approves v5 and the sequence ID is recorded.

## Dry run
Make three versions of a 90-second scene: assembly, rough cut and fine cut. Write a 5-item change list between each version. The versions must be distinguishable by filename and project sequence name.

## Guided practice
Use a supplied or self-recorded dialogue scene. Deliver a rough cut, feedback log, fine cut and proposed lock checklist.

## Independent assignment
Create a 3–5 minute narrative scene. Submit the project, three version records, feedback disposition, final runtime and signed/recorded approval field (use “not yet approved” if no approver exists).

## Common errors
| Symptom | Cause | Recovery |
|---|---|---|
| Changes overwrite prior work | No version strategy | Duplicate sequence and use version IDs |
| Review comments conflict | Multiple decision owners | Identify authorized decision owner and log resolution |
| Picture changes after turnover | Lock not controlled | Issue change request and notify all affected departments |
| Fine cut looks polished but story is unclear | Premature effects work | Return to story beats and performance |

## Knowledge check
1. What is the primary purpose of a rough cut? — Test story structure and completeness.
2. Why is picture lock operationally important? — It stabilizes downstream work.
3. What must a lock record contain? — Version, approval authority/date, runtime and exceptions.

## Assessment (100 points)
Version discipline 20; story structure 20; refinement and continuity 20; feedback/change control 20; lock/turnover evidence 20. Pass 75 with a recoverable project and traceable approved version.

## QC checklist
- [ ] Versions are preserved and clearly named.
- [ ] Notes are logged and dispositioned.
- [ ] Whole programme reviewed.
- [ ] Technical errors checked.
- [ ] Lock approval and turnover state are explicit.
