# CT-02 Lesson 10 — Professional Practice, Client Review and Archive

- Course: CT-02 — Film & Cinematic Editing
- Level: Professional Practice
- Estimated time: 3–4 hours
- Prerequisites: Lessons 01–09 and a completed capstone edit
- Environment: Project storage, review system and documented delivery specification
- Version/review date: 1.0 — 2026-11-16

## Learning outcomes
Learners can manage review rounds, maintain decision records, package a portable project, document rights and credits, and create a recoverable archive.

## Key definitions
- **Client review:** structured evaluation by an authorized stakeholder against the brief.
- **Revision round:** a bounded cycle of review notes, decisions and updated delivery.
- **Consolidation:** collecting required project media and dependencies into a controlled package.
- **Archive:** preserved project and deliverables intended for future retrieval.
- **Retention policy:** rule defining what is kept, where, for how long and who may access it.

## Professional principles
Professional editing includes communication, expectation management, file stewardship and ethical representation. A review copy must be clearly labeled as draft or approved. Notes should identify version and time reference. Archive only what the contract, law, retention policy and project owner authorize. Do not retain personal media indefinitely without a valid basis.

## Procedure
1. Confirm scope, approver, review rounds, delivery date, revision limits and acceptance criteria.
2. Publish a review copy only to the approved destination and access list.
3. Label the review version, date, runtime and status; distinguish timecode from source time.
4. Collect notes in one controlled log. Record author, time reference, request, priority and decision.
5. Resolve ambiguity before editing. Identify out-of-scope requests and obtain approval for cost/time changes.
6. Create a new sequence/version for each approved revision round.
7. Record accepted, rejected and deferred notes with reasons.
8. Before final handoff, consolidate project dependencies and test the package on a separate location or clean workstation when feasible.
9. Include project file, media manifest, fonts/plugins requirements, captions, exports, credits, rights notes and change log as appropriate.
10. Create checksums for critical deliverables where supported and verify copied files.
11. Apply the project retention policy; document archive owner, location, date and restore test.
12. Remove temporary/private copies only under the authorized retention and deletion process.

## Worked example
A client sends 18 notes across two versions. The editor groups duplicates, flags a request that changes the agreed runtime, and asks the designated approver to resolve conflicting notes. Accepted notes are implemented in v3; rejected notes receive a reason. The final package includes the approved project, media manifest, exports and a restore test record.

## Dry run
Create a mock review log with five notes: objective typo, subjective pacing request, contradictory shot request, out-of-scope runtime change and unclear timecode. Demonstrate how each is clarified and dispositioned.

## Guided practice
Package a short scene and reopen it from a different folder. Record missing dependencies and repair the package.

## Independent assignment
Submit a client handoff pack with final version, project, manifest, rights/credits record, review disposition, archive note and restore evidence.

## Common errors
| Symptom | Cause | Recovery |
|---|---|---|
| Notes refer to wrong frame | Version/time reference missing | Reissue review copy and log |
| Project opens with offline media | Dependencies not consolidated | Relink and test clean copy |
| Unapproved revision delivered | Status confusion | Enforce approval field and final manifest |
| Archive cannot be restored | No restore test | Test copy and document environment |

## Knowledge check
1. Why record note disposition? — It preserves accountability and prevents repeated ambiguity.
2. What proves a project is portable? — A successful reopen/restore test from the packaged location.
3. Should all source footage be retained forever? — No; follow authorization and retention rules.

## Assessment rubric (100)
Review/change control 20; communication and scope 15; project portability 25; rights/credits/privacy 15; archive/restore evidence 25. Pass 80 and successful project reopen is mandatory.

## QC checklist

- [ ] Notes are dispositioned.

- [ ] Package opens from a separate location.

## Version notes
