# CT-02 Lab 01 — Scene Breakdown, Coverage Map and Screen Geography

**Level:** Beginner → Intermediate  
**Estimated time:** 90–120 minutes  
**Software:** Any NLE with bins/folders, source viewer, timeline and markers; a spreadsheet or notebook may be used for logs.  
**Output:** Scene analysis, axis diagram, coverage map, labeled selects and a short assembly.

## Learning outcomes
By completion, the learner can identify dramatic beats, inventory coverage, map the axis of action, label usable takes and construct a spatially understandable first assembly.

## Prerequisites and materials
- A 30–90 second fictional dialogue/action scene with at least two camera angles or shot sizes.
- Permission to use all footage and audio.
- NLE installed; project storage with a backup.
- Scene-analysis and coverage-log worksheets from the CT-02 workbook.

## Concepts
A **beat** is a meaningful change in information, intention or emotion. **Coverage** is the collection of recorded shots available to build the scene. The **axis of action** is the imaginary line that helps preserve screen geography. A **select** is a source range chosen for possible use.

## Procedure

### A. Create a safe project
1. Create a project folder with `01_media`, `02_project`, `03_audio`, `04_exports`, `05_documents` and `06_review`.
2. Copy authorized source media into the media folder; retain the camera originals in a separate backup.
3. Create a new NLE project and save it inside `02_project`.
4. Set the sequence to match the intended source/delivery requirements. Record frame size, frame rate, audio sample rate and color-management assumptions. Do not guess missing metadata.
5. Import media without renaming the original files. Use bins or folders to group camera, audio and scene material.

### B. Analyze the scene
1. Watch the complete scene once without pausing.
2. Write a one-sentence scene objective.
3. Identify the beginning state, conflict, turning point and ending state.
4. Mark at least six dramatic beats with source timecodes.
5. Record what the audience knows at each beat and whose point of view dominates.

### C. Build the coverage inventory
1. Review every clip in the source viewer.
2. Record clip ID, camera/angle, shot size, take, source in/out, performance notes and continuity risks.
3. Mark usable ranges with source in/out values or NLE markers.
4. Identify missing coverage. Do not invent a shot that was not recorded.

### D. Draw the geography
1. Sketch the room from above.
2. Mark character positions, entrances/exits, props and the primary axis.
3. Add camera positions and their approximate viewing directions.
4. For each shot, record screen-left/screen-right and gaze direction.
5. Flag shots that cross the axis. Decide whether the crossing is intentional and whether a neutral shot or visible camera move makes it understandable.

### E. Create a first assembly
1. Create a sequence using the intended project frame rate.
2. Place the strongest establishing view first where the scene requires it.
3. Build the dramatic beats in a comprehensible order.
4. Use markers for unresolved continuity issues.
5. Avoid polishing transitions; first test whether the scene's information and performances work.
6. Save a new version with a clear name, such as `CT02_LAB01_assembly_v001`.

## Worked example
A two-person conversation has a master shot, two singles and a hand insert. Character A looks screen-right in the master. Character B looks screen-left. The singles preserve these directions. The hand insert is used only when the hand movement advances the scene. If one single reverses the gaze direction, verify camera position and source coverage before using it.

## Troubleshooting
| Problem | Check | Corrective action |
|---|---|---|
| Media is offline | File path and drive mount | Relink to the authorized media folder; do not overwrite originals |
| Scene geography feels reversed | Camera side and screen direction | Recheck axis diagram and angle metadata |
| No shot covers a beat | Coverage inventory | Use an available reaction or master only if it communicates the beat; document limitation |
| Assembly feels confusing | Beat order and audience knowledge | Rebuild the beat sheet before adding effects |
| Project settings are uncertain | Source metadata and delivery brief | Verify with media properties or production documentation |

## Submission evidence
- Project folder screenshot or folder listing.
- Scene objective and beat sheet.
- Axis/geography diagram.
- Completed coverage/selects log.
- NLE project and first assembly.
- A short note explaining one shot choice and one rejected shot.

## Assessment — 20 points
- Beat analysis: 5
- Coverage inventory: 5
- Geography/axis reasoning: 5
- Organized assembly and evidence: 5

**Pass:** 14/20 and no missing source-rights record.

## Quality gate
The project reopens; media is online; original sources remain preserved; sequence settings are documented; all selected shots can be traced to source clips; the assembly communicates the intended scene without relying on unexplained effects.

### 1. Professional brief

**Scenario:** A small post-production team receives an authorized 30–90 second two-person scene. The source package contains a master or wide view, at least two closer angles, and one action or reaction detail. The team must create an evidence-based scene breakdown, identify usable coverage, establish screen geography, and prepare a first assembly or a clearly labeled paper edit.

**Audience:** An editor or assistant editor who must understand the scene and hand the work to another editor without relying on undocumented assumptions.

**Deliverables:**
1. Source and authorization inventory.
2. Scene objective, beginning/ending state and beat map.
3. Shot/coverage inventory with stable source IDs and source ranges.
4. Top-down geography diagram with axis, camera positions, subject positions and movement.
5. Shot-by-shot spatial/continuity matrix.
6. Beat-to-coverage map and paper-edit order.
7. First assembly, if an NLE is available, or a paper-only edit plan.
8. Decision log, unresolved-gap list and QC evidence.

**Acceptance criteria:**
- Every selected shot can be traced to an authorized source asset and source range.
- At least six meaningful beats are supported by observable source evidence or explicitly marked as not covered.
- The primary action axis and each camera position are explained rather than guessed from screen direction alone.
- Eyeline, movement, prop state and adjacent-shot relationships are checked where relevant.
- No missing shot, reaction, prop state or event is invented.
- A reviewer can reconstruct the intended order and understand why each shot is selected.
- Executed work is distinguished from paper-only planning; no render, viewer test or application operation is claimed without evidence.

### 2. Learning and implementation objectives

By completing this lab, the learner can:

1. Produce a source/rights inventory that accounts for every in-scope asset and records unknowns.
2. Write a one-sentence scene objective and identify at least six evidence-backed dramatic beats.
3. Classify at least six source shots by scale, angle, coverage function and usable range.
4. Draw a top-down scene map that identifies the main action axis, camera positions, subject positions and important landmarks.
5. Build a shot matrix that records screen position, body orientation, eyeline target, movement vector and continuity-critical prop/action state.
6. Map each major beat to a primary shot and, where available, an alternative.
7. Prepare a paper edit or first assembly with source traceability and an explanation of at least two editorial decisions.
8. Identify unresolved coverage or spatial problems and propose a truthful, non-destructive remedy.

### 6. Core concepts and decision rules

| Concept | Working definition | Lab decision |
|---|---|---|
| Scene objective | What a character or participant is trying to achieve in the scene | State it in one sentence and cite the source evidence |
| Dramatic beat | A meaningful change in information, intention, action or emotion | Record before-state, trigger, after-state and evidence |
| Coverage | The set of recorded views/takes available to construct an event | Classify each shot by function, not by beauty alone |
| Master / wide | A view that may establish overall space and action | Test whether it actually communicates the necessary geography |
| Single / close view | A closer view of one subject or detail | Check performance, eyeline and what is excluded from frame |
| Insert / detail | A close view of an object or action detail | Verify object identity, state, chronology and hand/action continuity |
| Axis of action | A conceptual line through the primary interaction or movement | Derive it from blocking/action, then place cameras relative to it |
| Screen direction | The direction a subject appears to move or face within the frame | Compare it with the scene map and neighboring shots |
| Eyeline | The direction and target of a subject's gaze | Record target and uncertainty; do not infer a target without evidence |
| Source range | The in/out reference within the original media | Keep distinct from the sequence/timeline position |
| Paper edit | A written sequence plan linked to source ranges | Make decisions reproducible before assembly |
| Assembly | A first ordered construction used to test story and coverage | Prioritize intelligibility and completeness over polish |

**Decision rule 1 — action before axis:** Identify the primary interaction or movement first. Do not draw an arbitrary horizontal line through the frame and call it the axis.

**Decision rule 2 — camera side from evidence:** Use the top-down blocking map and camera orientation. Screen-left/right alone does not prove which side of the axis a camera occupied.

**Decision rule 3 — mark unknowns:** If the footage does not establish a gaze target, object state or camera position, write **unknown**. Do not fill the gap with an assumption.

**Decision rule 4 — beat before coverage:** Identify what changes, then choose the shot that communicates the change. A close-up is not automatically a beat.

**Decision rule 5 — spatial clarity is contextual:** An axis crossing is not automatically wrong. It must be motivated and legible in the sequence; a neutral shot or visible camera move is a possible strategy, not a guaranteed repair.

### 7. Reproducible implementation procedure

#### Phase A — Preflight and protect the source

1. Confirm the brief, intended audience, permitted use and required deliverables.
2. Complete the asset/rights table. Mark missing permissions and unknown restrictions.
3. Record source filenames, durations, frame rates/timebases where available and any timecode discontinuities.
4. Make a managed working copy or use a project that references protected originals.
5. Create the project structure and record its location.
6. Choose the paper-only or executed-assembly path. Do not describe one as the other.

**Verification:** Every in-scope source has a stable ID, a storage reference and a rights/permission status.

#### Phase B — Watch and describe the scene

1. Watch the full scene once without pausing, if footage is available.
2. Write a one-sentence objective using a character/subject, an action and a desired result.
3. Record the beginning state and ending state.
4. Identify the central obstacle, turning point and consequence.
5. Create a beat candidate list.
6. For each beat, record the before-state, trigger, after-state and source range.
7. Separate observable behavior from interpretation. For example, write “looks toward the door and stops speaking” before writing “is afraid someone has arrived.”
8. Record whose point of view guides each beat and what the audience knows at that moment.

**Verification:** Each accepted beat describes a change and has source evidence. A line, gesture or shot is not split into multiple beats unless a new change is supported.

#### Phase C — Inventory coverage

1. Review each source clip in full or document any clip not reviewed.
2. Assign a stable shot ID without changing the original filename.
3. Record camera, angle, shot scale, take, source in/out and usable handles.
4. Describe the shot's likely function: establish space, carry dialogue, show a reaction, reveal information, clarify action or provide a detail.
5. Record performance evidence separately from interpretation.
6. Note focus, exposure, sound, occlusion, framing, continuity and rights restrictions.
7. Identify which beats have primary coverage, alternate coverage or no verified coverage.

**Verification:** Every proposed paper-edit shot maps to a reviewed source range or is marked as a placeholder that cannot be treated as recorded footage.

#### Phase D — Build the top-down geography map

1. Identify fixed landmarks: doors, windows, desk, table, stairs or other stable features.
2. Mark each subject's starting position and any documented movement path.
3. Identify the primary interaction or movement that defines the axis.
4. Draw the axis and label its two sides.
5. Place each camera at an approximate position and show its viewing direction.
6. Mark any camera movement that crosses the axis.
7. Record subject facing direction, screen position and eyeline target for each relevant shot.
8. Mark unknown camera positions or blocked sightlines as uncertain.
9. Add a text description so the map remains understandable without color.

**Verification:** A reviewer can explain why each camera is on side A, side B, neutral/on-axis or moving. If this cannot be established, the camera-side field remains unknown.

#### Phase E — Complete the shot relationship matrix

For every adjacent pair proposed in the paper edit, compare:

- relative subject position;
- body orientation;
- horizontal and vertical eyeline;
- movement direction;
- action/prop state;
- camera side and any crossing;
- sound or dialogue continuity where relevant;
- the information the audience is expected to understand.

Do not mark a pair as passing solely because screen-left and screen-right appear consistent. Record **yes / no / unknown / not applicable** with a short reason.

#### Phase F — Build the beat-to-coverage map and paper edit

1. Put beats in the intended story order.
2. Assign a primary source shot/range to each beat.
3. Add an alternative only when a real source alternative exists.
4. Record the proposed cut point and the information the audience should receive.
5. Explain why the selected shot is stronger for this beat than the alternative.
6. Identify continuity risks, missing coverage and any chronology change.
7. Mark any transition that needs a neutral or re-establishing shot as a proposed solution, not as footage already available.

**Verification:** A second editor can follow the table and locate the proposed source ranges without guessing.

#### Phase G — Create the first assembly, if an NLE is available

1. Confirm the sequence specification from the brief or verified source metadata; do not guess.
2. Import or link the managed media copies while preserving source identity.
3. Build the scene in the approved beat order.
4. Use the strongest available establishing view only if it genuinely establishes the needed space.
5. Place shots using the paper edit and source ranges.
6. Add markers for unresolved geography, performance, sound or coverage problems.
7. Save a new version. Do not overwrite the source project or prior assembly.
8. Reopen the saved project if portability/reopen evidence is part of the submission.

No application-specific UI sequence is supplied. Exact menu labels, shortcut behavior, project settings and relink workflows vary by NLE and version and must be verified separately.

**Paper-only alternative:** Create the same shot order, cut rationale and unresolved-issue list in a spreadsheet or notebook. Label the result **paper edit only — no timeline executed**.

#### Phase H — Review and revise

1. Review the assembly or paper edit once for dramatic clarity.
2. Review again for spatial continuity and screen direction.
3. Review a third time for source traceability, performance integrity and chronology.
4. Ask an unbriefed reviewer, where available, to describe where the subjects are and what changes in the scene.
5. Record the exact question and unprompted response. If no viewer test occurs, record **not conducted**.
6. Revise only when evidence supports a change; preserve the previous version and decision rationale.

#### Phase I — Handoff

Provide the source inventory, beat map, coverage map, geography diagram, paper edit/assembly, issue list, version ID and a concise statement of what was and was not executed. List all unresolved questions and the person authorized to decide them.

### 8. Worked example — fictional café conversation

**All IDs, source ranges, positions and observations below are simulated teaching data. They do not describe real footage or an executed edit.**

**Brief:** Asha asks Ben to return a key. Ben places the key on the table but hesitates when Asha reaches for it. The scene ends with the key remaining between them.

**Top-down description:**
- Asha sits at the west side of a small table.
- Ben sits at the east side.
- The primary interaction axis runs west–east through the table.
- CAM-A is a wide camera north of the axis.
- CAM-B is a closer camera north of the axis, angled toward Asha.
- CAM-C is a closer camera north of the axis, angled toward Ben.
- CAM-D is an alternate camera south of the axis and is not used in the continuity-safe paper edit unless a motivated crossing is established.

**Simulated source inventory**

| Shot ID | Source ID / range | View | Camera side | Function | Observation / risk |
|---|---|---|---|---|---|
| SH-01 | SRC-A / 00:00–00:18 | Two-shot wide | A | Establish table and both subjects | Both subjects and key position visible |
| SH-02 | SRC-B / 00:04–00:14 | Asha medium | A | Carry request and reaction | Asha faces screen-right |
| SH-03 | SRC-C / 00:05–00:16 | Ben medium | A | Carry response | Ben faces screen-left |
| SH-04 | SRC-D / 00:10–00:13 | Key insert | A / detail | Clarify key placement | Verify key orientation and table position |
| SH-05 | SRC-E / 00:13–00:18 | Asha close-up | A | Show response to hesitation | Gaze target must be confirmed |
| SH-06 | SRC-F / 00:06–00:15 | Alternate Ben medium | B | Alternate performance | Axis side differs; crossing is not automatically usable |

**Simulated beat map**

| Beat | Before | Trigger | After | Source evidence |
|---|---|---|---|---|
| B01 — Establish the request | Key is with Ben | Asha asks for it | The request is explicit | SH-01 / SH-02 |
| B02 — Acknowledge the key | Ben has not responded | Ben looks down | Attention shifts to the key | SH-03 |
| B03 — Place the key | Key remains in Ben's hand | Ben sets it down | Key is on the table | SH-01 / SH-04 |
| B04 — Hesitate | Asha has not reached | Ben pauses and holds position | Transfer is not complete | SH-03 / SH-05 |
| B05 — Withhold the transfer | Key is available | Asha reaches; Ben does not release further control | Key remains between them | SH-01, subject to source verification |

**Proposed paper-edit order**

1. SH-01 to establish the room, subjects and key.
2. SH-02 for the request.
3. SH-03 for Ben's response.
4. SH-04 only if the insert clearly shows the same key and the correct action stage.
5. SH-05 for Asha's response, only if the eyeline target and chronology are supported.
6. SH-01 to show the unresolved final position.

**Decision:** SH-06 is held from the safe version because it is from the opposite axis side. It may be evaluated in a separate deliberate-crossing version only if the transition is motivated and the viewer can understand the new geography.

**Expected output:** A traceable paper edit or first assembly that communicates the request, placement, hesitation and unresolved transfer without inventing a completed handoff. The result is not an executed edit unless the learner actually builds and saves the timeline.

### 10. Guided practice

#### Exercise A — Beat evidence (25 minutes)

Use a 30–60 second authorized scene or the fictional café example.

1. Write the objective and beginning/ending states.
2. Identify six candidate beats.
3. Record before, trigger, after and source evidence for each.
4. Merge labels that describe the same continuing change.
5. Mark unsupported or uncertain beats.

**Success criteria:** Six evidence-backed beats or an explicit explanation of why fewer are supported; no beat label consists only of a shot size or camera angle.

#### Exercise B — Coverage function (25 minutes)

1. Inventory at least six shots or all shots available in the simulation.
2. Label each by shot scale, camera, source range and function.
3. Identify one primary and one alternate for at least three beats where coverage exists.
4. Record one rejected shot and the evidence-based reason.

**Success criteria:** Every selected/rejected decision cites a source range and a dramatic or continuity reason.

#### Exercise C — Geography map (30 minutes)

1. Draw a top-down map with at least two subjects, one landmark, one axis and two camera positions.
2. Add camera viewing directions.
3. Record screen position, body orientation and eyeline for each relevant shot.
4. Identify any crossing or uncertain camera side.
5. Write a text description of the diagram.

**Success criteria:** A peer can explain the camera sides and subject relationship without the learner verbally coaching them.

#### Exercise D — Paper edit or first assembly (30–45 minutes)

1. Create a six-shot sequence from the inventory.
2. Add the beat each shot serves.
3. Explain each transition and unresolved issue.
4. Compare a continuity-safe version with one deliberate crossing, if the source supports it.
5. Record whether a timeline was actually executed.

**Success criteria:** The two versions have distinct hypotheses; neither uses invented footage or undocumented mirroring.

### 12. Troubleshooting and rollback

| Symptom | Likely cause | Diagnosis | Safe recovery |
|---|---|---|---|
| Beat list becomes a shot list | Coverage labels were mistaken for dramatic change | Ask what changes before and after each candidate | Rewrite as a state change and cite source evidence |
| Camera side is unclear | Axis was drawn from frame direction rather than blocking | Revisit top-down scene map and camera orientation | Mark side unknown until verified |
| Reverse shots feel spatially wrong | Camera position or eyeline differs | Compare the pair in context and inspect the map | Select verified alternate coverage or re-establish geography |
| Insert seems to change object state | Different take/action stage or object orientation | Compare source frames and action chronology | Hold the insert or document the mismatch |
| A beat has no source support | Coverage gap or inaccurate brief | Search all authorized sources and production notes | Use truthful alternative, approved pickup or disclose limitation |
| Assembly is confusing | Beat order, POV or audience knowledge is unclear | Review without the shot list and ask for an unprompted summary | Rebuild the paper edit before polishing |
| Media is offline | Path, mount or dependency mismatch | Check the source inventory and storage reference | Relink to authorized copies; preserve originals |
| Project settings are unknown | Metadata or delivery requirements are missing | Inspect verified source metadata and written brief | Record unknowns and obtain an authorized decision; do not guess |
| Project fails to reopen | Missing dependencies or non-portable paths | Test a separate copy and inspect relink notes | Restore from the protected project copy and document the dependency |
| A transform appears to fix geography | Mirroring or rotation hides the underlying mismatch | Check text, logos, handedness, controls and factual details | Revert to source and choose an honest editorial repair |

### 14. Performance, security and portability

- Use proxies or low-resolution working copies only when the chosen workflow supports them; preserve a documented link to originals.
- Avoid duplicate media copies unless the storage and backup plan requires them.
- Keep source IDs stable across spreadsheets, project bins and handoff documents.
- Restrict access to footage containing personal or confidential information.
- Do not upload source material to cloud storage or AI tools without authorization.
- Document fonts, plugins, LUTs, audio assets and external dependencies if they affect the project.
- A folder screenshot is not proof that a project is portable. Portability requires a separate-copy reopen test and recorded result.
- Do not claim performance, playback or storage benchmarks without measurement.

### 17. Knowledge check and answer guidance

1. **Why is a dramatic beat not the same as a shot?**  
   A beat is a meaningful change in information, intention, action or emotion; a shot is a recorded view. One beat may span several shots, and a single shot may contain several changes.

2. **What must be recorded to support a beat claim?**  
   The before-state, trigger, after-state and source evidence/range, including uncertainty.

3. **Why should the axis be derived from blocking or action?**  
   The axis represents the spatial relationship of the interaction or movement. A line inferred only from screen direction can misclassify camera positions.

4. **Does a camera on the opposite side automatically make a shot unusable?**  
   No. It may be used when a motivated crossing or re-establishing transition makes the new geography understandable. The transition must be tested in context.

5. **What is the difference between source range and timeline position?**  
   Source range identifies material in the original clip; timeline position identifies where a selected range appears in a particular edit version.

6. **Why should an eyeline target sometimes be marked unknown?**  
   The footage may not establish what the subject is looking at. Naming a target without evidence invents spatial information.

7. **Name four fields in a useful coverage inventory.**  
   Stable source ID, camera/angle, shot scale, take, source in/out, performance note, continuity risk or coverage function. Any four well-explained fields earn credit.

8. **What should happen when no shot covers a major beat?**  
   Search authorized alternatives, evaluate a truthful restructure or approved pickup, and document the gap. Do not fabricate the missing action.

9. **Why is a neutral shot not a guaranteed axis-crossing repair?**  
   It may re-establish the relationship, but only if its timing and content make the new geography legible to the viewer.

10. **What is required before calling an assembly executed?**  
    A real project/timeline must be created and saved, with its version and evidence recorded. A paper edit is planning evidence, not execution.

11. **Why should source originals remain protected?**  
    They preserve provenance and allow recovery, re-editing and verification if a project or derivative is damaged.

12. **What does “Not tested” mean in the validation table?**  
    The check was not performed. It is not equivalent to Pass and must not be presented as validation.

### 18. Lab quality-control checklist

**Brief and source**
- [ ] Audience, scene purpose and acceptance criteria are recorded.
- [ ] Source rights, consent and restrictions are documented.
- [ ] Originals and previous project versions are preserved.
- [ ] Unknown source metadata is identified rather than guessed.

**Dramatic and coverage analysis**
- [ ] Objective and beginning/ending states are clear.
- [ ] Beats are meaningful changes with source evidence.
- [ ] Shot inventory covers all reviewed in-scope material.
- [ ] Selects and rejected shots have documented reasons.
- [ ] Missing coverage is disclosed.

**Geography and continuity**
- [ ] Axis is derived from the primary interaction/action.
- [ ] Camera positions and viewing directions are marked.
- [ ] Subject positions, body orientation and eyelines are checked.
- [ ] Movement vectors and action/prop states are compared.
- [ ] Crossings are motivated or flagged for review.
- [ ] Mirroring or other transforms are not used as undocumented repairs.

**Assembly and evidence**
- [ ] Beat-to-coverage map and paper edit are reconstructable.
- [ ] Executed timeline and paper-only plan are clearly distinguished.
- [ ] Project version and environment are recorded if used.
- [ ] Unresolved issues and decisions are handed off.
- [ ] All unexecuted or untested claims are labeled honestly.
