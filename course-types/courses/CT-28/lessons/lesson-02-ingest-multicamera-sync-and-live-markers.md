# CT-28 Lesson — Ingest, Multicamera Sync and Live Markers

- Course: CT-28 — Live & Streaming Content Editing
- Level: Beginner / Intermediate
- Estimated time: 90–180 minutes
- Prerequisites: Basic video/audio media literacy
- Environment: Record capture/streaming software, switcher/recorder, NLE and version; exact menus are product-specific
- Version/review: Verify current platform requirements and service terms before publication

## Learning outcomes
Explain the production concepts, carry out a reproducible workflow, identify risks and submit reviewable evidence.

## Definition and terminology
Ingest imports recordings and metadata; synchronization aligns sources; live markers flag moments for later highlight retrieval.

## Purpose and professional relevance
Use timecode, clap, waveform or visual sync references. Markers should include context and operator/source.

## Tools and alternatives
Use any lawful capture/streaming and editing system that meets the brief. Record software, hardware, firmware and platform versions. A spreadsheet can manage markers, rights and delivery. Do not assume a platform archive contains isolated source recordings.

## Step-by-step procedure
Copy and verify recordings; inventory source IDs; align sources; check sync at beginning/middle/end; import markers; map markers to timecode; create selects log.

## Worked example
A marker references the program clock, but camera recording begins late. Reconcile offsets before using it as an edit point.

## Guided practice
Synchronize three camera sources and produce a marker map.

## Independent assignment
Apply this workflow to an authorized recorded session. Include source timecodes, settings, approval status, risks and final delivery evidence.

## Common errors and recovery
Assuming shared start time; missing media; drift. Validate offsets and preserve original files.

## Assessment evidence
Submit media inventory, sync report and marker log.

## Knowledge check
1. Define the main concept in this lesson.
2. Why must source recordings and program output be distinguished?
3. How can a highlight be misleading?
4. What evidence should accompany delivery?

## Answer guidance
1. Use the definition and explain its role in the live-to-post workflow.
2. A program mix may not preserve isolated camera/audio sources or full-quality originals.
3. Removing context, qualifiers, responses or accurate time/source attribution changes meaning.
4. Source manifest, settings, timecodes, approvals, rights, QC and archive records.

## Quality-control checklist
- [ ] Source recordings and offsets documented.
- [ ] Full context reviewed for selected clips.
- [ ] Guest/music/venue/sponsor rights checked.
- [ ] Audio, sync and graphics validated.
- [ ] Current platform requirements verified.
- [ ] Privacy and retention policy applied.
- [ ] Final outputs and archive manifest reconciled.

## Further study
Use current official platform documentation, recording-device manuals and applicable event/participant release requirements.
