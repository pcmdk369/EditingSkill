# CT-29 Lesson — Mobile Timeline Editing and Story Assembly

- Course: CT-29 — Mobile Editing & Creator Workflows
- Level: Intermediate
- Estimated time: 90–150 minutes
- Prerequisites: Smartphone file management and basic camera use
- Environment: Record device model, OS, editor/app version, storage and export capabilities
- Version/review: Mobile app features and platform upload specifications change; verify current versions

## Learning outcomes
Explain the concept, perform a repeatable mobile workflow, diagnose common errors and document evidence.

## Definition and terminology
Timeline editing arranges clips, audio, titles and transitions in sequence. Mobile interfaces may constrain precision and screen space.

## Purpose and professional relevance
Build a story before adding effects. Use trim handles, split, ripple, track/layer controls and markers according to app version.

## Tools and alternatives
Use any currently supported mobile editor that meets the brief. A desktop editor may be used for final finishing if the phone cannot meet requirements. Check local/cloud processing, app permissions, subscription limits, export restrictions and backup availability before committing to a workflow.

## Step-by-step procedure
Import verified sources; set project dimensions/frame rate; create selects; assemble story; trim pauses; preserve dialogue context; add B-roll; review at full speed; save version.

## Worked example
A short tutorial should show the result, steps and outcome. Build the sequence in that order before titles.

## Guided practice
Overusing transitions; editing on proxy/low preview without final check; accidental ripple shifts. Review timeline and version checkpoints.

## Independent assignment
Complete a new mobile-first edit using authorized source material. Submit the project, export, capture/asset records, app/device version and QC evidence.

## Common errors and recovery
Submit project file and rough-cut review.

## Knowledge check
1. Explain the main concept in this lesson.
2. What device or app limitation could affect the workflow?
3. How should the output be checked before publication?
4. What should be documented in the handoff?

## Answer guidance
1. Use the definition and connect it to the mobile production process.
2. Storage, codec support, thermal limits, app permissions, export restrictions or version differences.
3. Full playback, metadata, audio, captions, framing, rights and current platform requirements.
4. Device/app versions, source inventory, project/export, approvals, rights and backup records.

## Quality-control checklist
- [ ] Device and app versions recorded.
- [ ] Original media backed up.
- [ ] Permissions and rights checked.
- [ ] Project settings match brief.
- [ ] Audio, captions and visual composition reviewed.
- [ ] Export reopened and played completely.
- [ ] Project and archive manifest delivered.
