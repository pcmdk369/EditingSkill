# EditingSkill Practice Asset Pack

**Status:** Authored fictional training data. These files are synthetic and contain no real people, clients, brands, copyrighted media, or personal information.

## Purpose

This pack gives learners a small, consistent production dataset for practicing media ingest, logging, editorial planning, consent/rights checks, captions, quality control, delivery manifests, and archive verification.

## Files

| File | Use |
|---|---|
| [asset-manifest.csv](asset-manifest.csv) | Ingest inventory, checksums placeholder, media metadata and status |
| [shot-log.csv](shot-log.csv) | Selects, shot descriptions, continuity notes and editorial decisions |
| [transcript.srt](transcript.srt) | Synthetic dialogue captions for timing, line breaks and subtitle QC |
| [rights-and-consent-register.csv](rights-and-consent-register.csv) | Permission and usage-gate practice |
| [delivery-qc-checklist.md](delivery-qc-checklist.md) | Export, review, handoff and archive checks |

## Fictional scenario

A small educational studio is producing a 60-second short video titled **A Better Morning Routine**. The story follows a fictional presenter preparing a workspace, planning three priorities, and beginning focused work. The supplied records describe hypothetical source clips; no actual media files are included.

## Suggested learner workflow

1. Copy the pack into a new project folder; never overwrite the source pack.
2. Review the asset manifest and flag missing or unverified metadata.
3. Build a selects list from the shot log; explain every exclusion.
4. Check the rights register before using any described asset.
5. Use the SRT file to practice caption timing and readability. The dialogue is fictional.
6. Export a test file in the target editor, then complete the QC checklist against the actual rendered output.
7. Record actual software name/version, export settings, test date, reviewer and evidence links in the learner's handoff.
8. Archive the project and verify copied files with generated checksums.

## Important limitations

- Descriptions in CSV files are not media files and cannot be used to render a finished video.
- Checksum fields are deliberately marked `NOT_GENERATED`; learners must calculate hashes from their own created files.
- Rights status is a training scenario, not legal advice or proof of permission for any real-world asset.
- The transcript is a practice source, not speech-recognition ground truth for an audio recording.
- A written checklist is not proof that a rendered output passed QC.

## Learning evidence

Submit the completed ingest log, edit decision list, rights gate, corrected subtitle file, export settings, QC results, and archive verification report. Label simulated checks separately from tests performed on actual media.
