# Production Workflows — EditSkill Specialist Module

## Scope
Coordinate end-to-end creative production, cross-discipline handoffs, versioning, review, approvals, delivery and archive.

## Core principles
Use a brief, asset manifest, naming convention, checkpoints and explicit approval gates; maintain one source of truth for specs and revisions.

## Task procedure
Map stages and owners; sequence dependencies; define handoff formats; track versions and review notes; protect originals; confirm final approval before release.

## Quality-control requirements
Audit handoffs, missing assets, revision scope, version mismatches, approvals, deliverable manifest and archive restoration.

## Required task record
For substantial work, record the brief, assumptions, source assets, rights/consent notes, selected software and version, key settings, steps performed, output paths, validation evidence and unresolved issues.

## Boundaries
- Load `../SKILL.md` for universal execution, safety and reporting rules.
- Consult the matching course in `../../../course-types/courses/` and existing repository references before inventing a new teaching sequence.
- Do not claim execution or successful export without tool confirmation.
- Preserve originals and request authorization before destructive, paid or externally published actions.
- If required tooling is unavailable, provide reproducible user-executable steps and clearly label them as instructions.

## Handoff
State inputs consumed, operations completed, output specification, QC result, known limitations and the next required human decision.

## PCMDK369™ academic and professional module compliance
This specialist module is governed by the [repository-wide Professional Developer & Academic Course Standard](../../../standards/PCMDK369-PROFESSIONAL-ACADEMIC-STANDARD.md) and [agent module requirements](../references/course-standard.md). ## Cross-discipline production gates

### Stage model
BRIEF → RIGHTS/ASSET INTAKE → PRE-PRODUCTION → ASSEMBLY → SPECIALIST FINISHING → REVIEW → APPROVAL → DELIVERY → ARCHIVE/RESTORE.

Each stage has an owner, input, output, acceptance criteria and exit decision. Do not advance a blocked asset or unapproved version.

### Handoff contract
Every handoff includes project/version ID, source manifest, frame rate/timecode, color/audio settings, linked assets, fonts/plugins/LUTs, captions, rights/consent, open defects, approval state and requested next action.

### Change governance
Use one source of truth for specifications. Record request ID, requester, exact change, affected versions, risk, owner, due date, approval and retest. Never overwrite an approved master; branch a new version.

### Review separation
Separate creative preference from factual/legal, accessibility, rights/privacy and technical QC. Route each issue to an authorized reviewer and retain the decision record.

### Archive and incident controls
Use checksums where available, redundant storage, access controls, retention/deletion schedules and periodic restore tests. For privacy or rights incidents, pause release, preserve evidence, restrict access and follow the responsible organization's escalation process.

### Production dashboard metrics
Track source completeness, open defects by severity, revision count, approval latency, failed renders, missing dependencies, delivery status and restore-test status. Do not treat engagement metrics as proof of editorial quality.
