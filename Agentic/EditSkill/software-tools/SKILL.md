# Software Tools — EditSkill Specialist Module

## Scope
Select and operate editing applications, command-line utilities, plugins and interchange formats with version-aware guidance.

## Core principles
Recommend based on task, device, budget, license, collaboration and output needs; distinguish supported features from assumed features; prefer portable formats.

## Task procedure
Confirm app/version/platform; inspect project compatibility; choose native or interchange workflow; record dependencies; provide exact tested steps only when known.

## Quality-control requirements
Check version compatibility, plugin dependencies, media relinking, fonts, color management, export settings and project portability.

## Required task record
For substantial work, record the brief, assumptions, source assets, rights/consent notes, selected software and version, key settings, steps performed, output paths, validation evidence and unresolved issues.

## Boundaries
- Load `../SKILL.md` for universal execution, safety and reporting rules.
- Consult the matching course in `../../../course-types/courses/` and existing repository references before inventing a new teaching sequence.
- Do not claim execution or successful export without tool confirmation.
- Preserve originals and request authorization before destructive, paid or externally published actions.
- If required tooling is unavailable, provide reproducible user-executable steps and clearly label them as instructions.

## Handoff
State inputs consumed, operations completed, output specification, QC result, known limitations and the next required human decision.

## Version-aware software selection and interoperability

### Selection criteria
Match application to task, OS/device, hardware, budget, license, collaboration, accessibility, file formats, plugin requirements and delivery constraints. Distinguish native project files from interchange and rendered deliverables.

### Verification workflow
1. Record exact app, version, OS and relevant plugin/codec versions.
2. Check current official documentation and known format limitations.
3. Build a minimal test project using representative media.
4. Test import, relink, effects, fonts, color management, audio channels and export.
5. Test project transfer to a clean location or second device where feasible.
6. Record unsupported features and acceptable fallbacks.
7. Recheck after major app or plugin upgrades.

### Interchange caution
XML/EDL/AAF/OTIO and image/audio interchange formats do not guarantee identical effects, transitions, color transforms or plugin behavior. Treat interchange as a conform starting point; compare the resulting timeline and rendered proof.

### Recommendation output
Provide primary option, viable alternative, required hardware/OS, licensing/cost caveat, compatibility risks, verified version/date and migration path. Do not invent a feature or claim a current price without evidence.
